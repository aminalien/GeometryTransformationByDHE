# Project workflow

- After completing and validating each user-requested code change in this project, commit the related changes with a descriptive commit message and push to `origin/main`, unless the user requests otherwise.
- This standing authorization applies to completed implementation work. Read-only investigations and planning do not require commits or pushes.
- Stage only changes belonging to the completed request; preserve unrelated user changes.
- Keep virtual environments, caches, generated previews, IDE workspace files, external shapefiles, and credentials out of commits.
- Report validation results, the commit ID, and push status after publishing.
