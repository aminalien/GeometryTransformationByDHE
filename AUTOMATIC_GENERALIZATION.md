# Mixed LTS levels and automatic generalization

The selection layer follows the supplied `Automatic_Map_Generalization_Operation_Selection.md` brief. It is a deterministic, configurable heuristic system, not a calibrated cartographic optimum or a learned model. Selection measures proposed geometries; execution constructs and validates the actual DHE transition space. This document distinguishes those two stages.

## Several operations in one level

Desktop and web workspaces provide a **Level operations** table. Select features and parameters in the existing editor, then **Add current selection / Add selection**. Select a row to edit it, use **Update action**, or Remove/Clear. When the table is nonempty, Preview and Apply process its rows together. An empty table retains the existing single-operation behavior.

Each source polygon can occur in only one row. A merge winner is included in its row's selected set. Targets generated by another row cannot be inputs at that same level. All rows start from the same actual current top, share one positive ΔZ (default 10), and end at the same target level. Multiple independent merge or aggregation groups are allowed. Aggregate identifiers are allocated in canonical source-index order, making results independent of table order.

The planner computes all targets/facets, rejects overlapping polygon targets, resolves neighbour updates jointly, and realizes the complete boundary once. Positive-area overlap between the transition regions of separate actions is currently rejected rather than selecting one surface arbitrarily; shared boundary contacts are conformed by the existing builder. Conflicting actions must have their parameters changed or be placed in separate levels. A failed level changes neither the applied model nor History.

Actual construction retains MEVVFS/MEV/MEF, the two-sided SewComplex helper, and JoinByFace. Each aggregation keeps distinct lower source cells and their roofs, with a separate upper aggregate cell. Historical ownership is not remapped. Unchanged isolated cells retain roof lifting without redundant wall bands. Single-action calls use the existing single-operation builder to preserve established behavior.

Aggregation planning validates the actual upper cell, beginning at the source roofs, and realizes the retained lower cells separately. It does not extrude their union into a temporary lower prism: sources touching at a point can make that artificial prism nonmanifold even though each actual cell is valid. Skeleton timing, shell incidence, vertex links, intersections, section checks and DHE validation remain required; no coordinate adjustment is used to accept such contacts.

## Automatic controls and transaction

Select current polygon features and open **Automatic settings / Run…** (desktop) or **Automatic…** (web). The run consolidates that selected family into one current feature, while retaining historical cells. Unselected features are not automatically assigned operations; their shapes may change through the existing neighbour-allocation rules. Affected context is reported.

All dependent levels are computed sequentially in one private background run. Only the final successful model is published, with all its intermediate History entries. No intermediate map is displayed. Cancel is checked between planning/construction stages; an individual DHE operator is not interrupted. Failure, cancellation, stale publication, or limits reached before completion preserve the original applied state. Use Undo/History afterward to inspect successful intermediate levels. Applying from an earlier history state replaces its later branch as before.

The defaults, also exposed as editable settings, are:

| Parameter | Default |
|---|---:|
| Starting scale denominator M | 10,000 |
| Scale multiplier | 2 |
| Constructed-level ΔZ | 10 |
| Minimum mapped width | 0.3 mm |
| Minimum mapped area | 0.09 mm² |
| Minimum mapped line length | 1 mm |
| Grouping gap threshold | 0.5 mm |
| Simplification tolerance | 0.1 mm |
| Constructed-level limit | 20 |
| Scale-advance limit | 20 |
| Candidate-set construction attempts per scale | 8 |
| Geometry / topology / cartography weights | 0.3 / 0.1 / 0.6 |

Map distances become ground distances by `d = mm × M / 1000`; mapped areas become `A = mm² × (M/1000)²`. Scale is coarsened after an intermediate constructed level, or when no acceptable level can be built at the current scale. Empty or unchanged candidate levels are skipped. Once consolidation succeeds, final representation selection uses that consolidation scale. Limits are explicit, adjustable, and bounded to 100 per setting.

**Final representation** offers Automatic, Polygon, Point, and Polyline. Point/line collapses are considered only after the selected family becomes one polygon: the existing collapse representations are terminal and cannot subsequently be merged by the polygon engine. An explicit final type must be realizable. Automatic may retain the polygon if that is the best feasible candidate. Elimination is not implemented or selected.

**Optional class constraint** requires every selected source to have the same nonmissing value in the chosen field. Otherwise one final feature would violate that constraint, and the run is rejected before construction. Leaving the field empty uses geometry/topology only. Merge winners retain attributes, aggregate results retain the chosen class, and lineage records the full selected ancestry. Mixed-level aggregate outputs also retain uniform attributes and source-member provenance.

## Indicators and candidate generation

For each current polygon the selector computes area A, perimeter P, vertex count, and dimensions of its minimum rotated rectangle. The short rectangle side is a **width proxy**, not a measurement of the minimum local width of a concave polygon. Elongation is long side / short side. At non-collinear vertices it computes signed turns θ. Rectilinearity is the fraction of turns satisfying `||θ|−π/2| ≤ π/18`; irregularity is the fraction of consecutive turns whose signs differ.

Simplification uses the existing topology-preserving construction with the current ground tolerance. Unchanged results are excluded. Smoothing uses one existing Chaikin iteration with ratio 0.25, and is considered only when rectilinearity < 0.75 and turning-sign irregularity ≥ 0.25. Both individual operations must improve their score relative to retention.

Merging candidates include shared-boundary pairs and maximal adjacency components whose union is a hole-free Polygon. Shared boundary length must exceed the existing modelling tolerance. The largest-area member is the winner, with index breaking ties. Proximity candidates use each polygon's four nearest selected neighbours within the scale-dependent gap, plus connected components of that symmetric proximity graph. Disconnected or holed unions propose the existing convex-hull aggregation. The graph is rebuilt from each constructed representation.

At the final polygon, Automatic considers point collapse when A is below the mapped-area threshold, and polyline collapse when elongation ≥ 4, the width proxy is below its threshold, and the long side reaches the minimum mapped length. Eligible candidates still compete with retention and beneficial polygon operations; small area alone does not force collapse. The existing visibility-kernel point and skeleton-ridge/fallback line builders determine geometric feasibility.

## Candidate cost and conflict resolution

The candidate score is

`J = (wg Eg + wt Et + wc Ec) / (wg + wt + wc)`.

All terms are bounded in [0,1]. Weights may be zero but cannot all be zero. Semantic compatibility and DHE validity are feasibility conditions, not invented soft scores.

- **Geometric change Eg:** mean of `min(1, area(S △ T)/max(area(S),area(T),TOL²))` and `min(1,Hh/D)`. For groups, S is the source union. Polygonal area loss to a dimensional target is a deliberate transformation cost, not a polygon-quality metric. Hh/D uses the existing sampled boundary/line/point Hausdorff routine, with reference spacing D/1000 and a 200,000-sample budget. Its sampling-only error bound is h/2. If NHD is unavailable, that term is omitted from this mean and the reason is saved; no value is fabricated.
- **External adjacency proxy Et:** `|NS △ NT| / max(1, |NS ∪ NT|)`, where NX is the set of outside-family polygons at distance ≤ TOL from proposed geometry X. This is a planning contact indicator measured against current neighbour shapes; it is not a proof of final DHE adjacency after joint neighbour updates.
- **Cartographic violation Ec:** for a polygon, mean of `max(0,1−A/Amin)`, `max(0,1−W/Wmin)`, the fraction of boundary edges shorter than the simplification tolerance, and turning irregularity (zero for predominantly rectilinear polygons). For a line, `max(0,1−length/Lmin)`; for a point, zero. A collapsed symbol has no inappropriate polygon area/width tests. These are heuristic legibility penalties, not empirically calibrated error measures.

Count-reducing group candidates are considered before individual candidates to pursue the requested one-feature goal. Within those classes, sort by J, then larger group, source indices, and operation name. Greedily select assignments with disjoint sources and no positive-area overlap between candidate polygon targets. This prefilter does not replace joint neighbour and transition validation.

Local target/facet failures identify their responsible action; retries exclude that action while retaining compatible choices. A joint target or transition conflict records the two actions, preventing that pair from being selected together again. A joint failure without action attribution tries progressively smaller prefixes in candidate order, down to a singleton, rather than claiming the first action caused it. Each scale permits at most `max_attempts` actual level previews; cached skips do not consume that budget. No failed level is committed.

Failed constructions are cached across scales only for the same private source state (including neighbours and historical cells), height increment and effective construction parameters. Group construction is independent of the displayed scale tolerance, while a changed simplification tolerance or smoothing parameters permits another attempt. Applying a private level invalidates the previous state's exclusions. Scale still advances within the configured limit to allow new proximity groups and parameter-dependent candidates. The final type is selected by score among feasible candidates, or restricted by an explicit final-type choice.

The complete final model receives the existing shell, intersection, section, primal/dual, exterior-symmetry and shared-interface checks. Reaching one feature does not assert that every soft cartographic preference was met: the final residual penalty is reported. There is no guarantee that every selection has a realizable consolidation under the available constructions and limits.

## History, evaluation, and reports

Mixed levels use an operation record named `batch`, with per-action names, selected indices, winners, parameters, and retirements. Single operations preserve their names. Existing source/target levels and history step identities remain available. Historical outlines follow all contributing action lineages, including intermediate aggregates.

Quantitative Evaluation remains **manual**. Last-operation analysis of a mixed level provides per-action feature/group scopes plus the affected context; whole-history analysis retains common comparable metrics. All eleven sampled sections still come from actual DHE boundaries. Planner measurements are prospective selection diagnostics and are not automatically generated journal evaluations.

The completed-run summary lists scale, Z interval, assignments, chosen costs, reasons, and affected context per level. **Save decision summary** writes JSON only when requested. It includes settings, measured source indicators, score terms, Hausdorff limitations, rejected candidates/constructions, final lineage/type, and residual violations. This supports reproducibility; it does not establish optimality or replace independent quality assessment.

Construction rejections preserve the nested `diagnostic`, including classification, failed/conflicting actions, planning stage, cell and offending edges where available. Reused failures record `cached_skips` and `last_scale`; `cached_constructions_skipped` totals avoided constructions. Incomplete runs have `status: "failed"`, a `failure_summary`, `last_scale` and `constructed_private_levels`; cancellation uses `status: "cancelled"`. Private levels in a failed report were not published. A reached limit also reports the last planning failure instead of hiding it behind the limit message.

## Programmatic and web interfaces

`session.preview_level(actions, dz=10)` returns one validated Proposal without applying it. Each action has `operation`, `selected`, optional `winner`, `tolerance`, `iterations`, and `ratio`. `session.preview(...)` remains compatible and delegates a single row. Normalization rejects duplicate source assignments and unknown fields.

`build_automatic_run(session, selected, settings, cancelled=..., progress=...)` returns a private AutomaticRun. `apply_automatic_run(session, run)` checks that its base state is still current and publishes the complete history prefix and final model. Rendering/serialization must succeed before callers publish. Core globals are restored after private planning, on success and failure.

New web POST endpoints are `/api/preview-level`, `/api/apply-level`, `/api/automatic`, and `/api/jobs/{id}/cancel`. Level requests supply `revision`, `actions`, and `dz`; automatic requests supply `revision`, `selected`, and `settings`. Existing single-operation routes remain compatible. One executor serializes DHE work. Automatic publication increments revision once, although History gains multiple levels. The original `/api/scene` remains available while the run is pending. Cancellation after publication cannot undo a committed result; use History instead.

Validation covers mixed dimensional contacts, several aggregates, duplicate assignments, order independence, overlapping targets, actual sections and evaluations, class constraints, automatic final types, deterministic choices, limits, late failures, cancellation, stale results, history restoration, native desktop controls, and web API/client control flow. Generated fixtures/previews remain outside commits. The supplied selection brief is preserved.
